# Atelye — Tailor Shop PWA (iOS-ready)

A device-bound, offline-first Progressive Web App port of the Atelye
tailor-shop management system (Farsi / Dari UI).

The original desktop build used a USB hardware-serial dongle. This PWA
replaces that with a **signed token bound to each phone's install**
(device-id generated on first launch, stored in `localStorage`, verified
with HMAC-SHA256 against the same master secret).

## What works

- **100% offline after first load** (service worker caches the whole app).
- **Data stays on the phone** in IndexedDB — same schema and features as
  the desktop build (customers, orders, inventory, expenses, fabric sales,
  SMS config, backup/restore).
- **Installable on iPhone** via Safari → Share → "Add to Home Screen". No
  App Store, no Mac, no Apple Developer account required.
- **Per-client licensing**: each client's phone gets its own token. Token
  copied to a different phone won't work (different device-id).

## Hosting — GitHub Pages (one-time setup)

1. Push this repo to GitHub (already done).
2. GitHub → **Settings** → **Pages** → under "Build and deployment", set
   **Source** = `Deploy from a branch`, **Branch** = `main` / `root`.
3. Wait ~1 minute. GitHub will show a URL like:
   `https://<your-user>.github.io/TailorshopIOS/`
4. That URL is what you send to clients.

## Client onboarding (per phone)

1. Client opens the GitHub Pages URL in **Safari** on their iPhone.
2. Tap **Share → Add to Home Screen** → name it → Add.
3. Launch the app from the home screen. An activation screen appears
   showing a 32-character **device code**.
4. Client sends you that device code (SMS / WhatsApp / email).
5. You run:
   ```
   python licensing-tool/issue_token.py
   ```
   Paste the device code, pick the client label → copy the printed token
   and send it back to the client.
6. Client pastes the token into the activation screen → tap **فعال‌سازی**.
7. App activates. Token is stored locally; no further activation needed
   unless the client clears Safari data or reinstalls.

## License model — how it differs from the USB version

| USB v3 | PWA |
|---|---|
| Key bound to USB hardware serial | Token bound to per-install device-id |
| Lost USB = new key needed | Cleared Safari data = new token needed |
| Key file on the stick | Token string pasted into app, stored in `localStorage` |
| HMAC-SHA256 over `label:drive_fp` | HMAC-SHA256 over `label:device_id` |
| MASTER_SECRET compiled into EXE | MASTER_SECRET in `index.html` (see **caveats**) |

### Caveats — read this

- **The `MASTER_SECRET` is in `index.html`.** Anyone technical can view-
  source the page and extract it, then mint their own tokens. This is an
  inherent limit of client-side-only licensing — the desktop EXE had the
  same issue, just harder to extract. For real protection against
  sophisticated tampering you'd need a server to issue tokens. For the
  tailor-shop audience this is good enough.
- **Clearing Safari storage or "Clear History and Website Data" erases
  both the license and the tailor-shop data.** Remind clients to use
  "Export backup" regularly (saves a JSON they can share to Files).
- **iOS Safari storage is evicted after ~7 days of app non-use.** Tell
  clients to open the app at least weekly, or iOS may free the IndexedDB.

## Updating the app

Edit files, commit, push. GitHub Pages redeploys automatically. Clients
get the new version next time they launch (the service worker caches but
refreshes in the background). Bump `CACHE_VERSION` in [sw.js](sw.js) to
force immediate refresh.

## Adding more client labels

Edit the `CLIENTS` list at the top of
[licensing-tool/issue_token.py](licensing-tool/issue_token.py) and add
entries like:

```python
{"id": 6, "label": "CLIENT-006", "name": "خیاطی نام جدید"},
```

Or just pick option **[Custom label]** at runtime and type one in.

## File map

```

├── manifest.json           ← PWA manifest (icon, name, standalone mode)
├── sw.js                   ← service worker (offline cache)

└── licensing-tool/
    └── issue_token.py      ← mints per-device license tokens
```
